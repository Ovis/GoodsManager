# 動作確認用サンプル

モックの架空商品64件、関連マスター、商品イラストを同梱しています。.NET 10 SDKと、起動済みのGoodsManagerを使います。追加のパッケージ・Python・Node.js・`mock` ブランチは不要です。

リポジトリ直下で実行します。先にブラウザで初期登録を済ませてください。

```sh
dotnet run --project tools/GoodsManager.SampleData -- --url https://localhost:7449 --login account.browser --collection マイコレクション
```

現在のアカウントのパスワードを、非表示の対話入力で入力します。接続先やログインIDを変える場合は引数を変更してください。パスワードの初期値は持たず、アカウント作成・再設定も行いません。

Windows側で実行して、別マシンのDockerで動くGoodsManagerへ投入することもできます。`--url` にブラウザで開くHTTPSの接続先を指定します。投入先マシンに.NET SDKを導入する必要はありません。

```sh
dotnet run --project tools/GoodsManager.SampleData -- --url https://goods.example.com --login account.browser --collection マイコレクション
```

投入先は `--collection 名前またはID` で指定します。省略時、参加中のコレクションが1件なら自動選択し、複数なら対話端末で番号を選びます。名前が重複する場合や自動実行ではIDで特定してください。投入先以外のコレクションは変更しません。

投入後、対象のコレクションを再読み込みします。新しい環境への投入結果は次の構成です。

- 通常商品62件（うち所持0が3件）、ゴミ箱2件
- 個体10点、複数ロット、個体メモ・固有写真
- 商品画像、複数写真、画像なしの商品
- 作品・シリーズ・キャラ・タグ・メーカー・販売元、状態・場所・購入先
- 検索用のチェック桁付きEAN-13。先頭の商品は `4901234500013`

初期表示の「所持あり」では59件です。「全商品」「所持数0」への切り替え、25件ごとのページ送り、重複確認、ゴミ箱からの復元などを試せます。

## 再実行と途中再開

同じコマンドを再実行しても、商品メモのサンプル番号で既存の商品を判定してスキップします。今回あらかじめ投入した64商品も認識します。既存の商品や、編集済み・ゴミ箱移動済みのサンプルは上書きしません。

実行記録は `artifacts/sample-data/` に、接続先・アカウント・コレクション・データ版ごとに保存します。同時実行を防ぎ、途中で停止した場合は同じ本文・変更キー・更新条件で再開します。パスワードやCookieは保存しません。DBを作り直して新しく初期登録した場合は、アカウントIDが変わるので別の実行記録を使います。

7日を過ぎた未確定要求、期限切れの未使用画像、実行記録の商品が接続先から消えている場合は停止します。登録状態を確認したうえで、必要なら `--state-directory artifacts/sample-data-retry` のように別の記録先を指定してください。既存サンプルは商品メモでも判別されるため、そのままスキップします。サンプル番号をメモから消すと判別できなくなるため、別の記録先で再投入する前に確認してください。

## 接続と証明書

接続先はHTTPSのオリジン（スキーム・ホスト・任意のポート）で指定します。`localhost`・ループバックIP・別マシンのホスト名やIPに対応し、パス・クエリ・フラグメント・URL内の資格情報は指定できません。リダイレクトは追従せず、通常のログイン・CSRF・重複検査・更新条件を通して登録します。証明書は通常の検証を使います。

ローカル証明書を別途指定する必要がある場合だけ、公開証明書を `--certificate パス` で指定します。証明書の完全一致・名前・有効期限を照合します。秘密鍵やPFXは指定しません。

自動実行時には `--password-stdin` を付けると標準入力からパスワードを1行読みます。実パスワードをコマンド履歴や保存スクリプトに直書きしないでください。
